# builder（`app/builder`）

辅助一个项目开发的 Harness：一台机器上常驻一个 builder，专门维护这个项目。它是一个中心化、自管理的 agent，这个项目的大部分开发与运维都在它上面做；它能维护自己的大部分代码，能写 script 与 html，html 在内网上展示。

实现与方案的差异照常记在 `实现与方案的差异.md`。

## 形态

- **一棵树**：目录是「结构」（一件事，如 `feat_x`、`weekly_report`），根也是一个；结构里的文件是「产物」（`prd.md`、`status.html`）。
- **聊天也在树里**：每个结构有一个主聊天（`main.chat`）；每个人可以开分支聊天，也是这个结构里的一个 `.chat`。聊天对所有人公开：所有人进来群聊，一起讨论、溯源一件事。没有用户自己的即兴会话。
- **builder 被 @ 才回**，回的时候带上之前的上下文。
- **待办**：结构里的待办，`status` 看进度。
- **界面**：内网上的网页，左边树、中间产物（md 渲染成文档，html 直接跑）、右边当前结构的聊天。

```
skill_eval.html
agent_trace.html
feat_x/
  main.chat
  zhang-review.chat
  status.html
  prd.md
  code_review.html
weekly_report/
  main.chat
  prd.md
  report_config.html
```

## 部署

- 一台机器常驻；树直接放在机器磁盘上（`BUILDER_HOME/tree`），机器用 rclone 之类同步到 OSS。持久状态（写前日志等）在 `BUILDER_HOME/state`。
- 内网身份由网关带来（具体方式还没定）：网关把身份放在一个请求头里（`BUILDER_USER_HEADER`，缺省 `x-builder-user`），值按 URI 编码。本机开发时网页自己带上填的名字。
- 大模型用公司内部的一个接口；还没接上之前先用 DeepSeek。

## 分步

| 步 | 内容 | 状态 |
|---|---|---|
| 1 | 树、产物、主聊天：三栏网页，多人实时群聊，存盘 | 做完 |
| 2 | @builder：被 @ 时带上这个聊天的上下文回答；能读写当前结构里的产物、建子结构 | |
| 3 | 分支聊天：每个人从主聊天开分支，在分支里 @builder 带上主聊天到分叉处与分支的上下文 | |
| 4 | 待办与进度：结构的待办，status 看进度 | |
| 5 | 溯源：builder 做的每一步挂在聊天下，按时间线看 | |
| 6 | 维护项目：项目代码、命令、提交；危险的动作在聊天里由人点头 | |
| 7 | 页面与 script：html 产物调 builder 写的接口 | |
| 8 | 自维护：改自己的 script 包与页面（运行中生效）；改插件走提交与重启 | |

## 现在的样子（第 1 步）

- **服务端**（`server/main.ts`）：两个自己的插件，没有模型、没有 agent。
  - `tree`：`tree_list`（整棵树）、`tree_create`（建子结构，名字只许字母、数字、`_` 与 `-`）。点开头的文件不算。
  - `chat`：`chat_read`、`chat_post`。说话的人是调用者（网关带来的身份），一行一条消息追加进 `.chat`；同一个聊天的写入排队，不互相覆盖；消息 id 是这次调用的 runId，崩溃后重新执行不会写两遍。
- **服务接口**：内网 HTTP（缺省 127.0.0.1:8090）。调用者取自身份请求头；所有人看得到所有的树与事件（会话公开）；静态文件：`/` 是网页，`/tree/` 是树里的文件（产物），`/vendor/marked/` 是网页渲染 Markdown 用的库（内网不一定连得上 CDN）。
- **网页**（`ui/`，原生 JS，不用构建）：左边树（每个结构固定有主聊天），中间产物，右边聊天；订阅事件流，`chat_post` 结束就把消息加进来，有人建了结构就刷新树。名字存在浏览器里。地址里的 `#路径` 指向选中的东西，可以发给别人。
- **本地跑**：`bun run builder`，浏览器打开 `http://127.0.0.1:8090`。配置见 `.env.example`。
