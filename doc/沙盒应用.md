# 沙盒应用（`app/sandbox`）

跑在 E2B 沙盒里的通用 Harness：

1. **当用户的一台小服务器**：接受、处理请求，有独立的数据存储。
2. **自带一个管理 agent，管它自己**：编写新的处理接口、更新自己的能力、框定对外服务的能力。

用 stdlib 搭，写法同 `app/mvp`：`server/` 是它的 Harness（装配配置、自己的插件与 script 包），`client/` 是和管理 agent 对话的终端，`config.ts` 是两边共用的配置；各应用共用的客户端与检查在 `app/pkg/`。实现与方案的差异照常记在 `实现与方案的差异.md`。

## 部署环境

- 沙盒在隔离的内网区域，进来的请求都经业务网关，可以认为是安全的：Harness 自己不做认证。
- 网关转发时带着签发给调用者的 JWT（`authorization: Bearer`），每个调用者的不同。沙盒相信 JWT 的内容；调别的服务（大模型 API、MCP、数据服务等）时以调用者的身份带上它。
- 没有管理员：谁能做什么由 Operation 区分。
- 大模型 API 是 OpenAI 协议，令牌放在请求头里。现在先用 DeepSeek 与它的 key 当 JWT。

## 分步

| 步 | 内容 | 状态 |
|---|---|---|
| 1 | 骨架：终端经 URL 连上，和管理 agent 对话 | 做完 |
| 2 | JWT：从进来的请求取下，认出调用者，调外部服务（先是大模型 API）时带上 | 做完 |
| 3 | 权限按 Operation 区分：调用者能调哪些 Operation；对外清单由插件管；对外请求的树能调什么 | |
| 4 | 数据：按包分开的存储 | |
| 5 | 管理 agent：写处理接口、试跑、装上、对外；装上的包自动成为它的工具 | |
| 6 | E2B：模板与启动脚本 | |

## 现在的样子（第 2 步）

- **服务口**：`serve.http`，TCP，缺省 8080，沙盒里监听 0.0.0.0（只有网关进得来）。它对外 `manager_say`、`manager_reset`、`manager_greet`，还有服务接口本来的 `/runs`、`/parks`、`/events`（现在谁都看得到全部，第 3 步按调用者分）。
- **调用者**：服务口把请求带的令牌记进调用者的凭据（只在内存里），树记下调用者（JWT 的 `sub`；不是 JWT 的取令牌的摘要）。调大模型 API 时带上这个调用者最新的令牌；过期了或重启后还没有，等他下一个请求带来新的。没带令牌的请求没有调用者，调不了大模型。见差异文档一.22。
- **插件**：stdlib 自带的（harness、time、ui、kv、package），加上这个应用自己的：
  - `fs`：工作区里的文件工具（pi 的编码工具），写与改不问人——工作区里只是草稿，把关在装上与对外。
  - `model`：只有 `model_complete`，不做语义压缩，凭据用调用者的；对话太长时用 `/new` 开始新对话。
- **管理 agent**：`manager`（对话，每个调用者一段，历史存在 kv）与 `agent`（agent 循环）从 MVP 的 `chat`、`agent` 复制过来，改了名字与人设，`agent` 去掉了压缩；第 5 步改成真正的管理 agent，到时写它们自己的测试。
- **状态**：都在 `SANDBOX_HOME`（缺省 `./.sandbox`）下：`state/` 是持久状态，`workspace/` 是工作区。
- **本地跑**：`bun run sandbox:serve` 起服务端，另一个终端 `SANDBOX_TOKEN=<令牌> bun run sandbox:manager ["第一句"]` 连上（令牌先用 DeepSeek 的 key）。连别处时设 `SANDBOX_URL`，大模型 API 换地址设 `SANDBOX_LLM_URL`。配置见 `.env.example`。
