# 沙盒应用（`app/sandbox`）

跑在 E2B 沙盒里的通用 Harness：

1. **当用户的一台小服务器**：接受、处理请求，有独立的数据存储。
2. **自带一个管理 agent，管它自己**：编写新的处理接口、更新自己的能力、框定对外服务的能力。

用 stdlib 搭，写法同 `app/mvp`：`server/` 是它的 Harness（只有装配配置与 script 包，插件都是 stdlib 的），`client/` 是管理员的终端，`config.ts` 是两边共用的配置。实现与方案的差异照常记在 `实现与方案的差异.md`。

## 分步

| 步 | 内容 | 状态 |
|---|---|---|
| 1 | 管理口与骨架：服务接口支持 TCP 上的令牌；管理员的终端经 URL 带令牌连上，和管理 agent 对话 | 做完 |
| 2 | 对外服务口：外部请求只能调已对外的 Operation；对外清单在持久状态里，由插件管（对外要审批）；对外请求的树只能调白名单里的能力 | |
| 3 | 数据：按包分开的 SQLite | |
| 4 | 管理 agent：写处理接口、试跑、装上、对外；装上的包自动成为它的工具 | |
| 5 | E2B：模板与启动脚本（超时自动暂停、来请求自动恢复） | |

## 现在的样子（第 1 步）

- **两个口**：现在只有管理口（`serve.http`，TCP，缺省 8081）。它对外 `admin_say`、`admin_reset`、`admin_greet`，还有服务接口本来的 `/runs`、`/parks`、`/events`：持令牌的就是管理员，什么都能做。对外服务口在第 2 步加，单独一个端口。
- **令牌**：`SANDBOX_ADMIN_TOKEN`。服务端监听在本机以外（沙盒里是 0.0.0.0）时必须有，不给启动即失败；本机开发可以不给。
- **管理 agent**：`admin`（对话，历史存在 kv）与 `agent`（agent 循环）先从 MVP 的 `chat`、`agent` 复制过来，只改了名字和人设；第 4 步改成真正的管理 agent，到时写它们自己的测试。
- **状态**：都在 `SANDBOX_HOME`（缺省 `./.sandbox`）下：`state/` 是持久状态，`workspace/` 是工作区。
- **本地跑**：`bun run sandbox:serve` 起服务端，另一个终端 `bun run sandbox:admin ["第一句"]` 连上。连沙盒时设 `SANDBOX_ADMIN_URL`（如 `https://8081-<沙盒 id>.e2b.app`）与 `SANDBOX_ADMIN_TOKEN`。配置见 `.env.example`。
