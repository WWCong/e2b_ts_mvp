# 沙盒应用（`app/sandbox`）

跑在 E2B 沙盒里的通用 Harness：

1. **当用户的一台小服务器**：接受、处理请求，有独立的数据存储。
2. **自带一个管理 agent，管它自己**：编写新的处理接口、更新自己的能力、框定对外服务的能力。

用 stdlib 搭，写法同 `app/mvp`：`server/` 是它的 Harness（装配配置、自己的插件与 script 包），`client/` 是管理员的终端，`config.ts` 是两边共用的配置；各应用共用的客户端与检查在 `app/pkg/`。实现与方案的差异照常记在 `实现与方案的差异.md`。

## 部署环境

- 沙盒在隔离的内网区域，进来的请求都经业务网关，可以认为是安全的：Harness 自己不做认证。
- 网关转发时带着签发给沙箱的 JWT。沙盒相信 JWT 的内容；调别的服务（大模型 API、MCP、数据服务等）时把它带上即可。

## 分步

| 步 | 内容 | 状态 |
|---|---|---|
| 1 | 管理口与骨架：管理员的终端经 URL 连上，和管理 agent 对话 | 做完 |
| 2 | JWT：从进来的请求取下，调外部服务（先是大模型 API）时带上 | |
| 3 | 对外服务口：外部请求只能调已对外的 Operation；对外清单在持久状态里，由插件管（对外要审批）；对外请求的树只能调白名单里的能力 | |
| 4 | 数据：按包分开的存储 | |
| 5 | 管理 agent：写处理接口、试跑、装上、对外；装上的包自动成为它的工具 | |
| 6 | E2B：模板与启动脚本 | |

## 现在的样子（第 1 步）

- **管理口**：`serve.http`，TCP，缺省 8081，沙盒里监听 0.0.0.0（只有网关进得来）。它对外 `admin_say`、`admin_reset`、`admin_greet`，还有服务接口本来的 `/runs`、`/parks`、`/events`。对外服务口以后单独一个端口。
- **插件**：stdlib 自带的（harness、time、ui、kv、package），加上这个应用自己的：
  - `fs`：工作区里的文件工具（pi 的编码工具），写与改不问人——工作区里只是草稿，管理员把关的是装上与对外。
  - `model`：只有 `model_complete`，不做语义压缩；对话太长时管理员用 `/new` 开始新对话。
- **管理 agent**：`admin`（对话，历史存在 kv）与 `agent`（agent 循环）从 MVP 的 `chat`、`agent` 复制过来，改了名字与人设，`agent` 去掉了压缩；第 5 步改成真正的管理 agent，到时写它们自己的测试。
- **状态**：都在 `SANDBOX_HOME`（缺省 `./.sandbox`）下：`state/` 是持久状态，`workspace/` 是工作区。
- **本地跑**：`bun run sandbox:serve` 起服务端，另一个终端 `bun run sandbox:admin ["第一句"]` 连上。连别处时设 `SANDBOX_ADMIN_URL`。配置见 `.env.example`。
