# 沙盒应用

跑在 E2B 沙盒里的通用 Harness，从零一步步搭，不沿用 MVP 的产品形态：

1. **当用户的一台小服务器**：接受、处理请求，有独立的数据存储。
2. **自带一个管理 agent，管它自己**：编写新的处理接口、更新自己的能力、框定对外服务的能力。

实现与方案的差异照常记在 `实现与方案的差异.md`。

## 部署环境

- 沙盒在隔离的内网区域，进来的请求都经业务网关（router），可以认为是安全的：Harness 自己不做认证。
- 网关转发时带着签发给调用者的 JWT（`authorization: Bearer`），每个调用者的不同。沙盒相信 JWT 的内容；调别的服务（大模型 API、MCP、数据服务等）时以调用者的身份带上它。
- 没有管理员：谁能做什么由 Operation 区分。谁能调哪个 Operation 由 router 按 JWT 校验过，沙盒相信转过来的调用，不再查。
- 大模型 API 是 OpenAI 协议，令牌放在请求头里。现在先用 DeepSeek 与它的 key 当 JWT。
- 数据两种都要：沙盒本地的，与外部数据服务（带调用者的 JWT 调）。

## stdlib 里已经有的

前几步给沙盒做的、放在 stdlib 里的通用部分（见差异文档一.22），搭的时候可以用：

- 调用者：服务接口从请求的 JWT 认出调用者，记在树上（`ctx.caller`），每条事件都带；每个调用者只看得到自己的树。
- 调用者的凭据（`stdlib/infra/callers.ts`）：令牌只在内存里，调外部服务时按调用者取出；`piLlm` 能用它调 OpenAI 协议的大模型 API。
