# 沙盒应用（`app/sandbox`）

跑在 E2B 沙盒里的通用 Harness：

1. **当用户的一台小服务器**：接受、处理请求，有独立的数据存储。
2. **自带一个管理 agent，管它自己**：编写新的处理接口、更新自己的能力、框定对外服务的能力。

用 stdlib 搭，写法同 `app/mvp`：`server/` 是它的 Harness（装配配置、自己的插件与 script 包），`client/` 是和管理 agent 对话的终端，`config.ts` 是两边共用的配置；各应用共用的客户端与检查在 `app/pkg/`。实现与方案的差异照常记在 `实现与方案的差异.md`。

## 部署环境

- 沙盒在隔离的内网区域，进来的请求都经业务网关（router），可以认为是安全的：Harness 自己不做认证。
- 网关转发时带着签发给调用者的 JWT（`authorization: Bearer`），每个调用者的不同。沙盒相信 JWT 的内容；调别的服务（大模型 API、MCP、数据服务等）时以调用者的身份带上它。沙盒自己不持有任何凭据。
- 没有管理员：谁能做什么由 Operation 区分。谁能调哪个 Operation 由 router 按 JWT 校验过，沙盒相信转过来的调用，不再查。
- 大模型 API 是 OpenAI 协议，令牌放在请求头里。现在先用 DeepSeek 与它的 key 当 JWT。

## 角色

- **调用者**：带着 JWT 经 router 进来的人或系统。同一个沙盒里有两类用法，由 router 按 Operation 分：
  - 搭建的人：调 `manager_*`，和管理 agent 对话，让它写接口、装上、对外。
  - 使用的人或系统：调管理 agent 写出来、已对外的接口（如 `guestbook_post`）。
- **router**：认证，按 JWT 校验能不能调这个 Operation，转发。
- **控制面**：从模板创建沙盒，管它的生命周期（超时暂停、来请求恢复、删除）。
- **外部服务**：大模型 API、MCP、数据服务，都在网关后面，都认调用者的 JWT。

## 流程

### 一、起来

1. 控制面从模板创建沙盒。模板里装好 Bun、ripgrep 与 Harness 的代码；配置（大模型 API 与数据服务的地址等）不含凭据，可以写进模板。
2. Harness 启动：装载插件与 script 包，再装载以前装上的包（`state/scripts/`），从写前日志恢复没做完的树，监听 0.0.0.0:8080。
3. 没人用时沙盒暂停（内存与磁盘都保留），来请求时恢复，接着跑。调用者的令牌在内存里，跟着保留；真重启了，恢复的树等调用者下一个请求带来新令牌。
4. 沙盒删掉，盘上的东西（本地数据、装上的包、写前日志）都没了。

### 二、一个请求怎么走

1. 调用者经 router 调 `POST /operations/<名字>`；router 校验过，带着 JWT 转进来。
2. 服务口把令牌记进调用者的凭据，起一棵树，树记下调用者。只认 `expose` 里的 Operation。
3. 树里按名字调别的 Operation：script 只能调公开的，照常过装饰器、写前日志；调大模型、外部数据服务时带上调用者的令牌。
4. 结束后结果交回调用者（也可以 `?async` 先拿 runId，之后取）。中途要人回答的问题（审批、追问）只推给这个调用者。
5. 每个调用者只看得到自己的树：`/runs`、`/parks`、事件流都按调用者分。

### 三、和管理 agent 对话

`manager_say` 把这一句连同这个调用者的对话历史交给 agent 循环。agent 能用的工具：工作区里的文件（`fs_*`，写与改不问人）、写段脚本一次做完（`harness_exec`）、装上 script 包（`package_install`，要问人）、问人（`ui_ask`）。对话按调用者分开存；工作区是整个沙盒共用的。

### 四、写一个新接口（核心闭环）

以「做一个留言板：能发留言、列出留言」为例：

1. **写草稿**：agent 在工作区写 `drafts/guestbook/index.ts`：一个 script 包，`post`、`list` 两个 Operation，声明 `api`，数据经数据的 Operation 存取。
2. **试跑**：`harness_exec { dir, operation, input }` 在解释器里跑草稿的 Operation，看结果、按报错改。
3. **装上**：`package_install`，先问发起这一轮的调用者；装进 `state/scripts/guestbook`，运行中换进内核，重启后还在。
4. **对外**：把 `guestbook_post`、`guestbook_list` 加进对外清单，也要问人。router 要知道有了这两个接口、谁能调（`GET /operations` 列出对外的与它们的入参出参）。
5. **被调用**：使用的人经 router 调 `guestbook_post`；树的调用者是他，数据存在 guestbook 包名下（所有调用者共用；要按人分，包里用 `ctx.caller` 区分）。
6. **看与改**：agent 看接口最近被调的情况与出错，改草稿、再试跑、再装上（正在跑的用旧的跑完）；不要了就撤下对外、卸载。

### 五、数据

两种都要：

- **本地**：沙盒盘上，按包分开，每个 script 包只读写自己的（按 `ctx.callerPackage`）。现在有 `kv`（一个键一个 JSON）；要加 SQLite（一个包一个库），接口的业务数据放这里。跟着沙盒暂停与恢复，沙盒删掉就没了。
- **外部数据服务**：在网关后面，以调用者的身份（带 JWT）调；不随沙盒走。

### 六、能力的边界

- **入口**：router 管谁能调哪个 Operation；沙盒只对外 `expose` 里的。
- **对外服务的能力**：对外的接口是 agent 写的代码，它能调所有公开的 Operation，包括 `package_install`、`fs_write`、`harness_exec`、`manager_say`。不加限制的话，使用接口的人经它就间接用上了搭建的能力（审批也会推给他）。所以对外请求的树要有能力上限：只能调数据、时间、别的服务接口等，调不到管理类的 Operation。
- **管理 agent 的能力**：装上的包自动成为它的工具（「更新自己的能力」）。

## 现在有的与缺的

| 环节 | 现在 | 缺 |
|---|---|---|
| 起来 | 本地能起；写前日志恢复；装上的包重启后还在 | E2B 模板与启动 |
| 请求 | 服务口、调用者、JWT 带出去、按调用者分开看 | 对外清单是装配配置里写死的 |
| 管理对话 | `manager_say`，按调用者分开存 | 管理 agent 还是 MVP 的人设与能力面 |
| 写接口 | 写草稿、试跑、装上 | 对外与撤下；看接口被调的情况；卸载；装上的包不是 agent 的工具 |
| 数据 | `kv` | SQLite；外部数据服务；草稿试跑时存的数据记在 `harness` 名下，不是草稿自己的 |
| 边界 | router 管入口 | 对外请求的树的能力上限 |

## 分步

| 步 | 内容 | 状态 |
|---|---|---|
| 1 | 骨架：终端经 URL 连上，和管理 agent 对话 | 做完 |
| 2 | JWT：从进来的请求取下，认出调用者，调外部服务（先是大模型 API）时带上 | 做完 |
| 3 | 调用者之间互相看不见：runs、parks、回答问题、事件流按调用者分 | 做完 |
| 4 | 本地数据：按包分开的 SQLite；草稿试跑时数据记在草稿自己名下 | |
| 5 | 外部数据服务：带调用者的 JWT 调（先用替身） | |
| 6 | 对外：对外清单运行中增减（要问人），对外请求的树的能力上限 | |
| 7 | 管理 agent：人设与工具（写接口的闭环、看接口被调的情况、卸载），装上的包成为它的工具 | |
| 8 | E2B：模板、启动与生命周期 | |

每步做完都能在本地跑通一段：4 之后接口能存数据，6 之后能对外被调，7 之后整个闭环由 agent 自己走完。

## 现在的样子（第 3 步）

- **服务口**：`serve.http`，TCP，缺省 8080，沙盒里监听 0.0.0.0（只有网关进得来）。对外 `manager_say`、`manager_reset`、`manager_greet`，还有服务接口本来的 `/runs`、`/parks`、`/events`：每个调用者只看得到自己的树，审批也只到发起这一轮的调用者那里。
- **调用者**：服务口把请求带的令牌记进调用者的凭据（只在内存里），树记下调用者（JWT 的 `sub`；不是 JWT 的取令牌的摘要）。调大模型 API 时带上这个调用者最新的令牌；过期了或重启后还没有，等他下一个请求带来新的。没带令牌的请求没有调用者，调不了大模型。见差异文档一.22。
- **插件**：stdlib 自带的（harness、time、ui、kv、package），加上这个应用自己的：
  - `fs`：工作区里的文件工具（pi 的编码工具），写与改不问人——工作区里只是草稿，把关在装上与对外。
  - `model`：只有 `model_complete`，不做语义压缩，凭据用调用者的；对话太长时用 `/new` 开始新对话。
- **管理 agent**：`manager`（对话，每个调用者一段，历史存在 kv）与 `agent`（agent 循环）从 MVP 的 `chat`、`agent` 复制过来，改了名字与人设，`agent` 去掉了压缩；第 7 步改成真正的管理 agent，到时写它们自己的测试。
- **状态**：都在 `SANDBOX_HOME`（缺省 `./.sandbox`）下：`state/` 是持久状态，`workspace/` 是工作区。
- **本地跑**：`bun run sandbox:serve` 起服务端，另一个终端 `SANDBOX_TOKEN=<令牌> bun run sandbox:manager ["第一句"]` 连上（令牌先用 DeepSeek 的 key）。连别处时设 `SANDBOX_URL`，大模型 API 换地址设 `SANDBOX_LLM_URL`。配置见 `.env.example`。
